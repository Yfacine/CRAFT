# CRAFT Gate

MAIN은 대상별 계획에서 각 Gate의 근거를 확인하고 진행 또는 보류를 기록한다. 작업 흐름과 역할은 [01 메인 계획서](01_main-plan.md)에 있고, 대상별 판정은 [04 대상계획 양식](04_target-plan-template.md)에 남긴다.

## 1 판정과 기록 원칙

Gate는 `PASS`(진행 또는 G03 인수)와 `HOLD`(보류)로 기록한다. 개별 실측 상태는 `PASS / FAIL / BLOCKED / NOT RUN`으로 구분한다.

[대상계획의 Gate 기록](04_target-plan-template.md#71-gate-판정-기록)에 판정 ID·시각, 적용 기준·후보, 증거 위치, 판정과 보류 사유·재개 조건을 행으로 남긴다. 재판정은 새 행으로 기록하고 이전 행을 보존한다.

## 2 단계별 Gate

| Gate | 판정 시점 | 통과 조건 |
| --- | --- | --- |
| G01 · 구현 착수 | 코딩 배정 전 | 필요한 원본 근거를 수락했고, 필수 관찰 목록·기준과 명세·계약을 확정했다. 해당되는 사전 정합성 검토를 마쳤다. |
| G02 · 실측 착수 | 품질·인수 TF의 독립 실측 전 | 코드 리비전과 배포물 지문을 연결해 후보를 고정했다. 기준 버전, 사용자 진입점, 환경·초기 상태·입력, 후보 실행 승인의 출처와 허용 범위를 확인했다. |
| G03 · 최종 인수 | 검토와 실측 후 | 확정 필수 목록 전체가 현재 후보의 증거와 연결되고 아래 인수 판정 조건을 충족한다. |

범위·필수 관찰 목록·계약 또는 합격 기대값이 변경되면 영향받은 범위의 G01을 다시 판정한다. 새 후보 또는 변경된 실측 기준·조건을 적용할 때는 G02를 다시 판정한다. 코딩 담당의 자체 테스트는 승인된 개발 범위에서 수행하며, 독립 실측과 인수 증거는 위 Gate를 따른다.

## 3 최종 인수 판정

MAIN은 해당 대체 범위에 대해 확정된 **필수 관찰 목록 전체**를 기준으로 결과를 찾는다. 각 필수 항목에 대상 후보와 승인된 조건으로 수행한 개별 `PASS`와 실제 증거가 있고, 요구된 독립 검토 결과가 연결되어 필수 결함이 해소됐을 때 인수한다. 이전 후보의 `PASS`로 현재 후보의 `NOT RUN`을 해소할 수 없다. 이전 후보의 `FAIL`은 보존하고, 현재 후보의 유효한 `PASS`와 결함 해소를 확인하면 현재 결과로 판정한다. 실패·영향 사례를 우선 확인한 뒤 현재 후보의 나머지 필수 증거 공백도 해소한다. 아래 조건 중 하나라도 해당하면 인수를 보류하고 사유와 재개 조건을 기록한다.

| 보류 조건 | 해소 기준 |
| --- | --- |
| 필수 목록 미확정 또는 필수 사례·관찰 항목·증거 누락 | 범위와 목록을 확정하고, 목록과 대조해 빠진 항목의 유효한 실측을 확보한다. |
| 코드 검토 대상과 실측 배포물 불일치 | 검토한 코드와 실행한 배포물의 지문 연결을 확인하고 해당 후보에서 영향받은 검증을 갱신한다. 같은 빌드 이름만으로 일치 판정하지 않는다. |
| 미확정 기대값 변경 또는 구 기준 결과 제출 | 원본 근거에 따라 MAIN이 기준을 확정하고 영향받은 항목을 확정 기준으로 다시 검증한다. |
| 필수 독립 검토 결과 누락 또는 필수 코드·정합성 결함 미해결 | 해당 후보·기준에 대한 검토 결과를 연결한다. 결함은 지정된 소유자가 수정하고 독립 검토가 해소를 확인한다. |
| 실행 환경·초기 상태·입력 불일치 | 승인 조건에 맞춰 실행하거나 근거가 있는 동등 조건을 기준에 확정한 뒤 해당 항목을 실측한다. |
| 필수 항목 `FAIL`·`BLOCKED`·`NOT RUN` | 실패 원인이나 차단을 해소하고 실제 결과와 증거를 갱신한다. |
