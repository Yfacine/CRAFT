### 3.2 MAIN·SUB 역할 및 인계 확인

2026-11-06 (한국 시간). Codex CLI의 읽기 전용 세션에서 직접 실행 판단과 팀 실행을 분리해서 확인했다. TOML로 다섯 전문 역할과 기존 단일 진입점을 파싱하고, 스킬 공식 형식 검사·문서 경로·MAIN 지침 로딩을 확인했다. 단일 ZIP 기능 요청에서는 MAIN 직접 실행을 선택했고 다섯 도구 사용 기준을 유지했다.

팀 검증 `SMOKE-ZIP-01/F01`에서는 자체 ZIP 두 개와 기존 Python 예제 CLI를 사용했다. MAIN이 다섯 전문 역할을 이름으로 실제 호출하고, 선행 담당의 반환 결과를 다음 담당에게 메시지로 넘겼다.

| 호출 역할 | 실제 인계와 결과 |
| --- | --- |

| `craft_rea` | 읽기 전용 검증 세션의 승인 정책으로 MCP 호출이 거부됐다. 기존 REA CLI 6.7.0으로 조사해 `note.txt` 한 항목을 확인하고 명세 담당에게 인계했다. |

필수 확인은 등록·문서 링크·역할 경계·정상 및 반례의 인계다. 제품 인수와 다중 유형의 범용성은 개별 대상 작업에 남긴다.

#### 3.3.1 재구성 검증 결과

- 정적 검사 통과. SUB 설정 10개와 운영계획의 호출명이 일치했고, 스킬 형식·문서 링크·Codex MAIN 지침 로딩을 확인했다. 최종 작성 경로 17개에 역할 간 상하위 중복이 없었고, 분석 역할에 대소문자가 다른 `APP/save.py`를 추가한 반례에서 충돌을 검출했다. 이전 단일 SUB 등록을 정리하고 해당 이름의 자연어 요청은 MAIN이 연결한다.
- 독립 정적 검토의 발견 사항 두 건을 반영했다. Craft 분석 `work/craft/`와 제품 생성 `work/implementation/`을 분리했고, 미해결 필수 코드 결함이나 필수 실측의 실패·차단·미실행이 있으면 인수를 보류하도록 했다. 최종 경로와 보류 조건을 다시 확인했다.
- Codex 읽기 전용 호출에서 새 SUB 5개가 모두 실제 응답했다. 합성 저장·재열기 사례에서 코딩 담당은 수정안을 제시했고, 코드 검토는 공백 손실을, TF 작업 설계는 중복 작성권을, TF 구현 정합성은 개행 검증 누락을, TF 품질·인수는 실측 미실행을 각각 반환했다. 실행 ID `01a1b054-ff9e-71f2-80cb-1edc37af2073`. 원시 출력은 `%TEMP%\craft-roster-smoke-b5d29817-afa2-454c-9113-3bc725799555\events.jsonl`에 있다.

확인 범위는 구성·역할 호출·반례 인계다. 읽기 전용 사례의 코딩은 수정안 제출까지 확인했고, 예제 코드 실행과 실제 제품 인수는 미실행이다.

#### 3.4.1 최신화 결과

- REA를 CRAFT 로컬 6.8.0으로 전환했다. 공식 npm 무결성과 로컬 잠금 파일이 일치했다. 호환 Node.js 24.22.2 Windows x64 ZIP의 SHA-256은 `CA1BFF5D8EAD13C9F2EA404A176DB46BD430704D5B5113734049FA365E7799E2`였고 공식 SHASUMS와 일치했다. ZIP에서 Node 실행 파일을 배치했다. [REA 릴리스](https://github.com/morluto/rea/releases/tag/rea-agents-6.8.0) · [Node.js 배포](https://nodejs.org/en/download/archive/v24.22.2)
- 당시 로컬 프로젝트 MCP 설정 `.codex/config.toml`과 [CLI 안내](references/REA.md)가 같은 로컬 REA를 가리킨다. CRAFT 안팎의 `codex mcp get rea --json`을 각각 확인했다. CRAFT는 새 로컬 실행본을 사용하고 바깥에서는 기존 등록이 조회됐다.
