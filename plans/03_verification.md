#### 3.3.1 재구성 검증 결과

- 정적 검사 통과. SUB 설정 10개와 운영계획의 호출명이 일치했고, 스킬 형식·문서 링크·Codex MAIN 지침 로딩을 확인했다. 최종 작성 경로 17개에 역할 간 상하위 중복이 없었고, 분석 역할에 대소문자가 다른 `APP/save.py`를 추가한 반례에서 충돌을 검출했다. 이전 단일 SUB 등록을 정리하고 해당 이름의 자연어 요청은 MAIN이 연결한다.
- 독립 정적 검토의 발견 사항 두 건을 반영했다. Craft 분석 `work/craft/`와 제품 생성 `work/implementation/`을 분리했고, 미해결 필수 코드 결함이나 필수 실측의 실패·차단·미실행이 있으면 인수를 보류하도록 했다. 최종 경로와 보류 조건을 다시 확인했다.
- Codex 읽기 전용 호출에서 새 SUB 5개가 모두 실제 응답했다. 합성 저장·재열기 사례에서 코딩 담당은 수정안을 제시했고, 코드 검토는 공백 손실을, TF 작업 설계는 중복 작성권을, TF 구현 정합성은 개행 검증 누락을, TF 품질·인수는 실측 미실행을 각각 반환했다. 실행 ID `01a1b054-ff9e-71f2-80cb-1edc37af2073`. 원시 출력은 `%TEMP%\craft-roster-smoke-b5d29817-afa2-454c-9113-3bc725799555\events.jsonl`에 있다.

확인 범위는 구성·역할 호출·반례 인계다. 읽기 전용 사례의 코딩은 수정안 제출까지 확인했고, 예제 코드 실행과 실제 제품 인수는 미실행이다.

이 검증은 현황판의 로컬 연동과 합성 실행을 대상으로 했다. 실제 대상 복제와 SUB 배정은 대상별 실행에서 관찰한다.

## 4 후속 검증 기록

작업공간 후속 검증은 대상 버전 또는 지문, 실제 명령과 환경, 입력, 결과·실패·미실행, 근거 위치를 해당 이력에 남긴다. 개별 제품은 [대상계획의 실측 결과](04_target-plan-template.md#42-실측-결과)와 [Gate 판정 기록](04_target-plan-template.md#71-gate-판정-기록)에 증거와 판정을 연결한다. 도구를 바꿀 때는 [도구 도입 및 업데이트 이력](references/README.md#도구-도입-및-업데이트-이력)에 적용 버전과 날짜를 기록한다.
