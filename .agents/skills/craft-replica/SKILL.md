# CRAFT 복제품 개발

[메인 계획서](../../../plans/01_main-plan.md), [Gate](../../../plans/02_gates.md), [대상계획 양식](../../../plans/04_target-plan-template.md), [레퍼런스 목록](../../../plans/references/README.md)을 읽고 기존 대상의 계획·실행 기록에서 이어간다.

실제 대상의 복제 실행을 시작할 때 MAIN은 [현황판 절차](../../../plans/references/Monitor.md)에 따라 별도 CLI를 한 번 열고 반환된 `StatePath`를 보관한다. 단계 전환, SUB 호출·결과, 인계와 Gate 판정이 확인되면 MAIN이 해당 상태를 갱신한다. 대상계획에 기록한 실제 근거를 사용한다. 현황판 연결에 실패하면 이유를 기록하고 대상계획의 작업 흐름을 이어간다.

## 전문 역할

- MAIN은 [역할 배정](../../../plans/01_main-plan.md#3-역할-배정)과 선행조건에 따라 필요한 SUB를 호출한다. 완전한 신규 대체 범위에는 다섯 레퍼런스를 활용하고, 부분 보완에는 영향받는 분석과 기존에 유효한 근거를 연결한다.
- SUB는 배정된 기능 ID, 입력 리비전, 정확한 작성 경로, 실행 권한과 자원만 사용한다. 분석·검토 역할은 제품 코드를 읽기 전용으로 다루고 자신의 기록 경로만 작성한다. 제품 코드와 앱·하네스·테스트 작성권은 `craft_coder`에 있다.
- 선행 입력이나 쓰기 소유권이 확정되지 않으면 해당 작업을 MAIN에 돌려보낸다. 인계에는 대상 리비전, 근거, 실행 명령과 상태, 미확인 사항을 포함한다.

## 조사부터 인수까지

1. **착수와 분석.** 원본 버전·접근 범위를 정하고 필수 관찰 목록을 초안으로 작성한다. REAP 질문, REA 관찰, replica-skill 명세, Craft Anything 재현 방법, CLI-Anything 자동화·출력 비교 방법을 연결한다. 근거별 제공자·소비자·착수 필수 여부·인계 수락을 기록한다. 같은 GUI 등 공유 자원은 사용권, 입력 사본, 사용 순서, 초기화와 반환을 확인한다. 격리된 독립 작업은 병렬로 진행한다.
2. **구현 전 확정.** 필수 근거가 수락되면 MAIN이 `기능 ID → 인수 사례 ID → 필수 관찰 항목 ID` 목록을 원본 근거와 연결한다. 신규 대상이나 파일 형식·입출력 계약 변경은 정합성 TF가 원본 근거·명세(계약)·필수 목록으로 사전 검토를 마친다. 후보·구현 위치·실측 결과는 후보 단계의 입력이다. 인계·공유 자원 위험에는 작업 설계 TF를 호출한다. MAIN은 필요한 검토를 마친 뒤 목록·기준과 명세를 확정한 범위부터 코딩을 배정한다.
3. **코딩과 독립 검토.** 코딩 담당은 구현·자체 테스트 후 코드 리비전, 배포물 지문, 명세·인수 기준·테스트 버전과 재현 명령을 제출한다. MAIN은 후보를 고정하고 코드 변경마다 별도 코드 검토를 배정한다. 요구 추적에 영향이 있으면 정합성 TF가 고정 후보의 구현 위치·검증 결과까지 대조한다. 수정은 MAIN을 통해 각 소유자에게 반환한다.
4. **실행과 인수.** 품질·인수 TF가 고정 배포물을 실제 사용자 진입점에서 실행한다. 도면은 저장물과 종료 후 새 프로세스의 재열기 상태를 분리한다. CLI는 배포된 명령에서 정상·오류 종료 코드, 표준 출력·오류, 부분 파일과 기존 출력 상태를 각각 관찰한다. MAIN이 확정 필수 목록 전체를 결과와 대조하고 [인수 판정](../../../plans/02_gates.md#3-최종-인수-판정)을 적용한다. 목록 미확정, 필수 증거·독립 검토 누락, 배포물·기준·실행 조건 불일치, 미해결 필수 결함, `FAIL`·`BLOCKED`·`NOT RUN`이 있으면 인수를 보류한다.

## 막혔을 때

- 연결이 실패하면 레퍼런스의 준비 조건을 확인한다. 허용된 동일 도구의 CLI/MCP 경로를 사용할 수 있다. 마지막 성공 산출물과 실패 근거를 남겨 독립적인 작업을 이어간다.
- 테스트의 입력·관찰 방법 변경과 합격 기대값 변경을 구분한다. 기대값 변경은 분석 담당의 원본 근거와 MAIN 확정을 거친다. 이전 기준과 실패 증거를 보존하고 새 후보에서 실패 사례와 영향받은 필수 사례를 재검증한다. 원본 조건이 같은 근거와 영향 밖 분석은 적용 범위를 기록해 재사용한다. 복제품 실측은 실행한 배포물·기준 버전·실행 조건에 귀속한다. 이전 `PASS`와 현재 `NOT RUN`이면 보류하고, 이전 `FAIL`은 보존하되 현재 유효한 `PASS`와 결함 해소를 확인하면 현재 결과로 판정한다.
- 원본 자동화는 기준값 수집 경로로 구분한다. 원본 없이 복제품이 필수 결과를 생성하는지도 대상 범위에서 확인한다.
